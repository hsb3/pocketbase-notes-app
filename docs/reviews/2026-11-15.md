## Verification

Regression checks were observed failing against pre-fix code before passing:
external login redirects, pending login/reset/registration controls, invisible
verification failures, unsafe API-test targets, and ordinary-account admin links.
The capability API initially failed the authentication contract because the
unregistered route returned the static app instead of an authenticated JSON result.

Completed checks:

- Frozen dependency install, dependency audit, Biome, frontend/config build,
  operational-script type checks and diff whitespace validation.
- Full Chromium and WebKit scenarios: login, persistence, private files, rich
  editing, conflicts, draft protection, navigation, registration disabled,
  capability failure and cross-tab account switching.
- Explicit signup-enabled scenarios in both browsers: delayed real account
  creation, injected verification network failure, visible retry and successful
  verification request/navigation without duplicate account creation.
- Live PocketBase/Mailpit/RustFS API checks for email token round trips, stored
  file bytes, ownership, unsafe input rejection, revision conflicts and capability
  authentication/association/revocation.
- Real local scheduled S3 backup, followed by read-only checks for disabled,
  missing, fresh, stale and inaccessible backups. Tests restore their settings.

The test stack used separate named volumes and loopback ports. Existing local
services and Railway records were not used as mutable regression fixtures.
Documentation received a separate read-only accuracy and consistency review.

## Delivery boundaries

Hosted CI and native amd64 execution have not run for this branch. Browser checks
used local Chromium and WebKit, not physical Safari/mobile hardware. OAuth provider
login and legacy real-mail deployment drills were not exercised. The new backup
check validates listing metadata, not archive bytes or restoration.

The Railway read-only freshness check reports the last automatic backup as stale.
The earlier credential repair successfully created/downloaded a manual backup;
the next scheduled run must pass before automatic backup recovery is established.
No external alert scheduler is provisioned by this change. Configure one using the
[backup runbook](../../deploy/README.md#backup-health-and-credential-rotation).

After delivery, verify the new capability route on staging, run the backup
freshness check after the scheduled backup, and close issues only with the
corresponding delivery evidence.
