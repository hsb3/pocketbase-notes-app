# R2 design decisions

| Question | Decision and evidence | Rejected alternative |
|---|---|---|
| Where does the title live? | Preserve ordinary ProseKit blocks. Emphasize the first paragraph with CSS. Return inserts the next paragraph. R1 already derives the title across adjacent marks up to the first logical break and caps only the projection. | A second input or forced heading changes the document, paste behavior or Return semantics. |
| Where do previews come from? | Derive a virtual `excerpt` in the notes list-request hook before standard enrichment and field selection from stored R1 `text`. Omit the first logical line, fold whitespace and take up to 120 Unicode code points. Existing notes need no rewrite. Restrict custom export to this computed value. | A persisted field requires a schema change and backfill. Truncating the beginning of `text` would often repeat the title. Downloading `body` to call the old `bodyText()` defeats the list budget. |
| What owns the first save? | The editing session allocates one 15-character lowercase alphanumeric ID with Web Crypto when entering Compose. POST only on the first valid document. Keep the same ID for navigation and later PATCHes. The R1 contract reserves reconciliation after an uncertain outcome for R3. | Generating the key after the first response makes a lost response indistinguishable from an unsaved create. |
| How do old accounts get Notes? | A forward migration provisions missing defaults for ordinary users in one transaction. Preserve all existing defaults by ID. Check the unique index, the standard folder key and exact cardinality. R1 already provisions future users. | Ensure-on-auth misses dormant accounts and adds a write to login. A seed-only fix misses ordinary accounts. |
| How soon does Compose accept typing? | Preload the same editor module used to mount the surface when the list becomes available. On activation, mount and focus the editing view as part of the gesture when warm. Preserve its instance across layout changes. Measure the input event, not download completion. | Awaiting a create response, routing round trip or another tap before focusing consumes the one-second budget. |
| What can run the tests? | The two disposable Make targets already build assets and run real PocketBase, Chromium and WebKit on shared loopback. Place R2 tests in their existing discovery paths. Add narrowly scoped steps for upgrade, codegen and existing CI drills that actually need a different boot or binary. | Host servers, host browsers and asserting focus after a Playwright helper focuses the editor all give the wrong evidence. |

The approved Round 1 study uses a single document on phone, with Compose at the bottom right, and adjacent folders, list and editor at both wider widths. The 390px move, search, reading and formatting screenshots inform later increments. The R2 screen shows only available actions. Evidence reviewed locally under `~/.local/share/agent-artifacts/pocketbase-notes-app/` includes `design-review-01.md`, `apple-notes-references/study-v2.html` and its seven `round1-*.png` images.

R1 remains authoritative for the stored fields, rights and revisions. PocketBase 0.40.1 requires explicit custom-data export for virtual fields. Its default exports every custom key once enabled, so hide other custom keys and keep the existing search-key hide. Verify the exact wire response and privacy on the pinned server before consuming the new field.
