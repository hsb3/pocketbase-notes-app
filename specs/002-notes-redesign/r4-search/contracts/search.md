# R4 search contract

## Records list

Use the singleton PocketBase JS client. Read `GET /api/collections/notes/records` through `getList(page, 20, options)`. Extract the active predicate from inside `listNotes` in `src/features/notes/data.ts`. Both the ordinary and search paths use this same value. The folder predicate belongs only to the ordinary folder path. The server’s existing notes list rule restricts the authenticated collection to users and the record owner to that authenticated ID.

| Search option | Exact value |
|---|---|
| filter | Shared `deleted = ""` followed by ` && ` and `pb.filter("search_key ~ {:pattern}", { pattern })`, with the escaped pattern defined in the [model](../data-model.md). |
| sort and paging | `-updated,-id`, page size 20, normal PocketBase total counts. Previous/Next page through every match. |
| fields | `id,folder,title,updated,snippet` |
| query parameter | `searchTerm` carries the trimmed original query for server-side snippet selection. Use the SDK’s query option. |
| request | Independent request key (`requestKey: null`), `cache: "no-store"`. No expand, folder restriction, body request, detail fetch or attachment download to display a row. |

Within the existing notes list hook, branch on presence of `searchTerm` in `e.requestInfo().query`. Validate marked requests before enriching their rows. Require the nonempty trimmed single-line term, at most 160 code points, page size 20, canonical filter, exact fields and sort above, and no expand or skipped totals. An invalid marked request returns 400. To check the filter reproduce the fixed active predicate and the SDK’s JSON-string quoting of the escaped bound value; test parity on punctuation. Never run a second records query from the hook. Core applies the ordinary list rule and runs the query before the list hook. This validation constrains the search response contract, not the general records API or its database query cost.

For each marked row derive `snippet: {before, match, after}` from its original text. Enable custom-data export as R2 does for excerpt. Extend the enrich hook’s virtual-field allowlist to the server-populated snippet and existing excerpt, while continuing to hide the search key and arbitrary other virtual fields on all records. Ordinary list/detail, relation expansions, realtime and editor reads keep their existing shapes. The projection for the search request excludes full `text`, body, tasks, attachments, user and comparison key. There is no new collection, public route or change to the five access rules.

A normal search returns HTTP 200 with PocketBase’s list envelope. A hit has a nonempty marked string. A first-page miss reports totalItems zero and an empty items array. A caller with B’s valid token and an anonymous caller get the same empty result for A’s unique term. Opening an authorized active note still uses the ordinary detail reader and R3 session checks.

## Navigation and focus

1. On `/folders/$folderId` validate `page`, `q` and `sp`. Keep positive safe-integer pages, omitting defaults. Drop `sp` without a query. Accept a single string, trim and cap by Unicode code points, discard controls/newlines and structured values. Accept finite numeric/boolean scalar values as their spelling if the router has parsed a direct query string. Generate URLs through TanStack search serialization so a submitted string such as “001” round-trips. Treat invalid values as absent. A normal search uses all active folders regardless of path. A genuine empty page beyond the last result page returns to the last valid result page using replace; page 1 with zero results is the empty state.
2. Keep one labeled search form. Editing has no network or navigation effect. Submit from a folder replaces its URL with the same folder/ordinary page, new query and first result page. Submitting from a selected note navigates to that folder search via the normal guarded PUSH. Paging in search replaces `sp` only. Empty submission, Clear and Escape from the search field clear it and restore that folder’s original page, with focus on Search. Folder navigation starts the destination’s ordinary list. Keep typing/IME and normal Tab navigation available. Enter on a focused result opens it.
3. For a result opened from a folder list, PUSH the existing `/notes/$noteId` detail route with that list’s position in history state. Keep search text out of the note path. The wide side list reads the submitted search/page from position while the detail is active. Keep the detail selection and query unchanged until a departure is accepted. If Keep editing cancels a submitted search from the side list, restore the previously submitted field value and editor focus. For another result selected from that side list REPLACE the current detail, preserving the previous folder-search history entry and updating row focus in origin. Record that a search entry underlies the detail even on wide screens. If a direct note has no origin, its normal Back fallback remains its real folder. Use the query-bearing folder destination as fallback when an explicit origin exists but traversal is unavailable. For a search initiated on a selected note, the intervening PUSH to its folder search establishes the return entry before opening the next result.
4. Use the ordinary link/history blocker for every result change. Never set local document selection, dispose a draft, or fetch the next document before the existing guard permits navigation. Clean leaves proceed; a dirty save flushes first. On a failed save, Keep editing preserves the original note/focus, Save and continue awaits acknowledgment, and Discard opens the intended result without overwriting the saved version. Back (browser or editor) restores the URL, field value, correct result page, scroll and row focus after the matching rows load. Restore only once per return, scoped to the matching folder/query/pages. If a saved edit removed the row from results, focus Search. A detail refresh may use preserved history state; a pasted bare detail URL follows normal direct-link behavior.
5. A query change starts a loading state, an error gives an announced error with Retry for that query, and only a completed zero-hit search shows “No matching notes” with Clear. Announce the result count politely without stealing focus. Preserve ordinary “No notes yet.” At 390 px put one search form and Compose in the list footer above the safe area, outside its scrollport; remove absolute-button overlap. At the existing 768 px breakpoint put Search above the scrollport and keep Compose in the header. Only one focusable instance of each control is visible. Folder names, long unbroken snippets and mark spans wrap without widening the grid. Use the app’s semantic accent/foreground pair on mark, native link semantics, visible keyboard focus, and both themes.
