# Verify R3 against real notes

These are implementation and R6 gates. The planning commit delivers the procedures. Start at the repository root with the [disposable-runner prerequisites](../../../docs/testing/verification.md#disposable-docker-gates). It builds the app and runs actual PocketBase, Chromium and WebKit on private loopback with generated credentials, bounded resources and project-scoped cleanup.

## Five SC-003 scenarios

Define five named, parameterized cases tagged `@sc003` in `tests/e2e/save-resilience.spec.cjs`. Run each at 390, 810 and 1440 px in both configured projects. Use a fresh ordinary owner per case/width. Use the fixtures' API from outside the intercepted page for assertions. The owner list must show exactly one intended note on recovery, with the original ID, expected full body and exact revision. Check the previous valid version before recovery. A deliberately refused first create has zero rows until successful Retry. Install a status observer before typing to catch even a transient Saved for unacknowledged text. Reopen in an independent owner context to check the final result. Register routes before the triggering gesture, scope by method and record path, release held routes in cleanup and close extra contexts.

|---|---|---|

## Timing, guards and invalid input

- **SC-002.** In the page use a single monotonic time origin for the final real input, outbound write, known failure and visible retry feedback (e.g. capture input/fetch settlement and DOM mutations without changing the results). Record the actual millisecond deltas. Require pause-to-request ≤1000 ms and known-failure-to-visible-Retry ≤1000 ms. In a separate healthy write, hold the *real successful response* for at least 3000 ms, type again while held, and hold the next response separately. Assert continuous Pending/Saving then Pending for newer typing, with zero stale Saved transitions before the latest acknowledgement. Report actual delay and both latencies per engine/width.
- **Leave and sign-out.** Exercise SPA Back and Forward, note and folder links, another Compose, Account and sign-out. Keep editing preserves the draft. Discard leaves the last valid server body intact. Save and continue waits for all generations and repeated failure retains the editor. Open sign-out within the debounce interval and wait beyond it before choosing Discard. Assert no queued write escapes while the choice is open. The original owner remains authenticated until the chosen transition succeeds. Check cancellation, focus return, keyboard-only controls and both themes. Use an activated page, observe a real native beforeunload on reload/close, dismiss to keep words, then accept a deliberate departure. Verify a clean page leaves without warning. Record any engine/device limitation explicitly.
- **Invalid writing.** Use a saved ordinary note. Clear it and then exceed 102400 encoded document bytes with multibyte text. Check the reason and retained input, exact old body/revision and no false Saved. Correct and Retry each. Test the byte boundary including JSON overhead, new whitespace-only exit and a create cleared while its response is held. Retain R2's mention/image and attachment-only coverage.
- **Reconciliation failures.** Exercise failed owner read, duplicate-ID 400 plus unreadable record, newer revision with matching text, JSON key reordering, formatting differences, ordered-file mismatch, lost PATCH on unchanged baseline and unavailable/reload failure. Use deterministic unit tests for permutations and a live foreign-ID collision/deleted-source fixture for the wire outcomes. Never issue another create after a confirmed unreadable collision. Preserve the current local words for copying.

## Commands and release evidence

1. Before each implementation slice, run its new regression cases on the R2 behavior and retain the first substantive red assertions. Keep these separate from missing prerequisites. After implementation run `bun test tests/unit`, `bun run lint`, `bun run knip`, `bun run build`, `python3 scripts/ai-context.py check` and `bun run docs:build`.
2. Run `make test-api-contained` and `make test-browser-contained`. These are the disposable equivalents of the roadmap's live-stack/API/browser checks. Default browser discovery must include the new cases. Save numeric timing and named outcomes with engine, width, revision and result, using only fixture data.
3. At R6 run the following from Bash with the **planned** resilience browser profile installed by T002. Each round runs five scenarios × three widths × two engines = 30 tests, with one worker and zero retries. Require 30 passes per round and ten consecutive complete rounds (300 passes), with zero skips, missing cases, duplicate notes, overwrites or lost drafts. Stop on the first failure, keep its evidence, fix and start a new series at round one. Preserve the per-invocation teardown deadline.

```bash
for round in {1..10}; do
  echo "SC-003 round $round/10"
  make test-browser-contained CONTAINED_PROFILE=resilience || exit 1
done
```

The profile selects this spec and tag inside the existing browser container. It must check the expected scenario/width/project set and results from the Playwright report, including a failure for a missing case even if the runner exits zero. At R6 attach the ten round counts and the independent three consecutive full-suite runs to the stabilization evidence. Record actual phone, OS, date and result for the keyboard, native leave and expiry checks. Emulation and the R3 planning review supply no physical-phone proof.
