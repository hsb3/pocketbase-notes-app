# R3 design decisions

| Decision | Source and consequence |
|---|---|
| Extend the existing save loop. | `src/features/notes/draft.ts` already debounces for 500 ms, joins concurrent flushes and tracks generations. Its `retryable` flag handles only a narrow body-validation 400. Keep the last submitted snapshot through uncertainty. Starting a second save queue would allow the debounce, Retry and Back to race. |
| Compare an owned record before repeating an uncertain write. | `scripts/test-notes.ts` exercises duplicate POST, equal and different snapshots, revision races and an unreadable collision. `data.ts` already reads ordered attachments and the body. Full structural comparison tolerates PocketBase changing JSON object key order. Comparing plain text loses formatting and comparing the editor's current body loses edits made in flight. [R1 recovery contract](../../../docs/features/notes.md#recovering-an-uncertain-save-in-r3) |
| Keep a suspended draft in tab memory across sign-in. | `Workspace` keys `Library` by user, disposes its draft on unmount and reads existing notes by route. A component ref alone cannot survive the login route. Park the draft outside that component before unmount, hide all owner data while locked and restore only after verified ordinary-user authentication. Use the existing login flow for password, OAuth and MFA. Disk storage or credentials in the draft would extend its lifetime unnecessarily. |
| Adapt the old guard and dialogs. | At `b94195fa47eb0585d120e477911c6c333509faa4:src/features/entries/entry-editor.tsx`, see `accountId`, `useBlocker`, `save`, `reload`, `signIn` and the leave/reload alert dialogs. Reuse the owner-ID check, 401/403 and masked 400/404 handling, resolver and confirmation order. Keep R2's writable editor and autosave. The historical editor disabled typing during writes, replaced its draft on success and restored a previous token after a mismatch. Those behaviors break R3. |
| Use the router resolver for SPA transitions and the browser warning for hard exits. | R2's Back and Compose pre-flush before routing, and `/auth/logout` clears the auth store on route entry. Route every destructive intent through one decision before mutation. Browsers control unload dialog wording and require user activation. Full-page departure cannot wait for asynchronous saving. [Browser unload behavior](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event) |
| Inject only the fault. | `tests/e2e/notes.spec.cjs` already holds a real response and observes the save status. Playwright can fetch the real write before aborting delivery. A fabricated success or a dropped request before commit cannot prove lost acknowledgement. Keep the real API as an independent observer. [Playwright Route](https://playwright.dev/docs/api/class-route) |
| Repeat inside the existing containment boundary. | `scripts/run-contained.sh` accepts only enumerated profiles, streams the e2e directory, runs one worker on both projects and cleans up at minute 29 plus teardown. Add a narrow browser profile for one SC-003 round. Repeat fresh invocations ten times at R6 to keep the deadline per round and expose the first failure. The ordinary browser target continues to discover the cases. [Current gates](../../../docs/testing/verification.md) |
