# Private records and action responses

All custom paths below start with `/api/notebook` and bind `$apis.requireAuth("users")`. Read owner identity only from e.auth. Use request-scoped e.app, then only tx inside transactions. Bind every value. A guest/expired token gets 401, a different auth collection 403, a foreign or missing target 404 with the same message. Check target ownership before reporting revision, state, deadline or folder information. No response includes another writer's IDs, note metadata or file contents. Standard collection routes keep their PocketBase denial conventions. Return the action response only after runInTransaction has committed. Look up missing records deliberately. Translate only absence to 404 and let database faults surface as failures. Read responses and action confirmations are private and uncached.

| Method and path | Request | Successful response |
|---|---|---|
| POST /notes/{id}/move | JSON object with revision and folder | 200 with id, user, folder, deleted, revision |
| POST /notes/{id}/delete | JSON object with revision | 200, same projection |
| POST /notes/{id}/restore | JSON object with revision | 200, same projection |
| GET /recently-deleted?page=N | Optional positive safe integer page, default 1 | 200 with page, perPage (20), totalItems, totalPages, serverNow (ISO UTC with Z), items. Each item contains only id, folder (possibly empty), title, revision, deleted (PocketBase UTC string) and deadline (ISO UTC with Z). Empty result has zero totals and an empty array. |
| GET /folders/{id}/delete-preview | No body | 200 with id, name, activeCount and snapshot (SHA-256 lowercase hex) |
| DELETE /api/collections/folders/records/{id} | Existing records API. Supply query parameter snapshot from preview | 204 without body |

The DELETE path above is absolute. id and folder IDs are 15 lowercase ASCII letters or digits. Never use a move destination supplied as an owner override. A missing, fractional, string, out-of-range or stale note revision is 409. Require a JSON number that is a positive safe integer. A malformed body, unknown key, invalid/same/unavailable destination or unsupported state (including current-revision delete twice, move of trash or restore of active) is 400. Unknown destination and foreign destination have identical errors. Check revision before state/deadline, so a stale repeat of a successful transition returns 409. An owned, still-present note already expired with the current revision gets 410 on restore. After purge it is missing (404). No failure writes any field. Reject body modifiers and client timestamps. Existing ordinary PATCH cannot change folder/deleted, hard DELETE remains unavailable to writers. Body-only saves continue through the existing transactional revision hook and validation. A stale editor cannot win against an action.

On a current-revision request, validate the raw stored date before treating the note as active, retained or expired. A corrupt nonempty value fails closed (500); log its ID privately. Folder preview/confirmation aborts on any such member. Ordinary PATCH and authorized detail reads also check the stored value. [Raw-date and transaction rules](../data-model.md#clock-and-purge-progress)

Read trash rows and count from one transaction/snapshot with one server cutoff, binding the authenticated user's ID and canonical UTC cutoff. Filter `user = {:user} AND deleted > {:cutoff}` plus the [canonical SQL predicate](../research.md#deadline-and-comparison-engine) on both count and page, order by deleted DESC, id DESC, limit 20 at (page−1)×20. Reject unrepresentable offsets or malformed page (400). Compute deadline per row from its actual deleted value. Do not accept client filter, sort, expand, clock or owner. Use the record detail route with a minimal owner/id/folder/deleted/revision projection for single-action reconciliation, including a retained tombstone. Active-list exclusion applies to ordinary owner collection lists, folder lists and marked search, including totals/snippets. Direct owner view by known ID still returns a valid tombstone (including expired until purge), and related-record expansion follows the target view rule. The editor rejects tombstones. Keep body and search_key out of the trash list.

For folder preview and the DELETE hook use one shared snapshot function. Load the owned folder and all linked members in id order (id, user, revision, deleted). An unexpected foreign member violates the relation invariant: abort without mutation or disclosure. Count only currently active rows. Compute `$security.sha256(JSON.stringify([folder.id, rows.map(r => [r.id,r.revision,r.deleted])]))`. The same canonical types/order must be used for both reads. The digest is a concurrency precondition, never a credential. Default folder always returns 400. For the authenticated owner, preserve bare DELETE on a genuinely empty custom folder (204). Bare DELETE with any linked note returns 400. A supplied stale token returns 409 even if the folder is now empty. In onRecordDeleteRequest re-read folder, recompute and compare inside tx. Update each member at its expected revision, assign e.app = tx and call e.next() once to delete the folder. Throw on any write or comparison failure to roll back every row. Keep account-deletion cascades working on their existing model path.

## Interrupted requests

Freeze intent (session epoch, id, revision, original state, destination or snapshot) before sending. Ignore late callbacks after owner/route/selection changes. Disable duplicate submissions while pending. On a lost response, display an uncertain status and offer **Check again**. Re-read through the same authenticated session before enabling another write. For a note, exactly revision+1 and the intended state confirms the visible outcome. For restore verify folder against the original/fallback and require active. For delete require a valid deletion instant and original folder. For restore, capture the row’s folder and the loaded unique default ID before submit. A folder deleted after that row was read changes the revision, so a stale action requires a new row and decision. An unchanged baseline permits an explicit retry at the original revision. Any other winner requires a refresh and a new decision. Never retry automatically with a newer revision. For an ambiguous folder delete, verify current credentials first. A 404 for the previously owned folder and a fresh owner folder list without it establish that it is gone. A still-owned folder requires a fresh preview and confirmation. For a previously owned note, verify current credentials for the same owner before treating a fresh detail 404 as gone; for Restore also refresh the owner trash page. A definite 404 on Restore or Confirm after a competing purge/folder removal follows the same presence checks. Report only the observed disappearance; its author is unknown. Failed verification or refresh is inconclusive and retains the read-only Retry. [Close and Check again on each surface](navigation.md#uncertain-actions) On account switch discard the old overlays, selections and pending UI callbacks. Retain dirty words only via R3's same-owner in-memory recovery.
