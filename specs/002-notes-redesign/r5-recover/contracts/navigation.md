# Library controls, history and focus

Use the existing authenticated library routes and 768 px breakpoint. Recently Deleted is the reserved URL `/folders/recently-deleted`. The hyphen distinguishes it from real record IDs. Put its labeled destination after the real folders, above Account. At 390 show Folders, the trash list or the editor as the single visible region. At 810/1440 keep the folder column, trash list and an empty document column. Never open retained writing in an editable pane. Show title, localized date **and time with time zone**, and Restore on each row. Use a semantic time element whose dateTime is the exact server deadline. The server clock controls recovery. Use serverNow and the earliest row deadline to schedule a refetch by elapsed time. Cap each timer at 2,147,483,647 ms and re-arm after long waits. Re-read on tab return. A 410 is authoritative even when a device clock is slow.

Use the checked-in shadcn DropdownMenu, Sheet, AlertDialog and Button. Give each overlay an accessible title and description, trap focus, support keyboard and return focus explicitly across menu/sheet handoffs. Only persisted active notes have note actions. The busy/uncertain states must remain distinguishable from confirmed success.

## Pending writing

Move selection and explicit Delete confirmation are the commitment points. Opening or cancelling an overlay leaves independent autosave alone. At commitment, hold one intent bound to the active draft, baseline, session and selected target. Keep other actions out while the R3 guard waits for any in-flight write and flushes all pending generations. Do not send the metadata command until the outcome is known. A clean draft proceeds immediately. Capture the revision **after** the successful flush. Neither a menu-open snapshot nor the revision of a different selected note is valid.

On a failed flush reuse the R3 leave choices. Keep editing or Escape cancels the action and resumes the same draft with editor focus. Save and continue retries, checks the same session/draft and submits only on a confirmed clean baseline. Discard explicitly abandons local edits. Use the last acknowledged revision as the action precondition, never a revision taken from an intervening writer. On discard, reinstall the saved baseline for the still-open note. Adapt the existing finish callback, which currently disposes the draft before navigation. A metadata continuation must receive the intended id, baseline and latest acknowledged revision. An unresolved lost save must first be reconciled, or abort the metadata intent with recovery available. A stale result never triggers a second action at a fresh revision.

Keep the submitting overlay modal so typing cannot race the baseline swap. Guard route traversal while the request is outstanding. Use the uncertainty controls below after the request settles. For a dirty or conflicted draft retain its words and R3 Copy draft/manual-copy path. A stale content save racing another context's delete produces 409. R3's active-only detail recheck classifies a tombstone or a subsequently purged 404 as unavailable, verifies the owner session where required, and offers Copy draft. Never clear the editor, report Saved, reload over local words, or recreate the note on this path. Recovery also works when the clipboard API refuses permission.

A definite stale move or note delete (409) ends that intent. Re-read the active note for the same owner. For a clean draft, show the newer saved version or Note unavailable and return focus to Note actions or Back respectively. Require a new action. For dirty writing, preserve it and use R3 conflict or unavailable recovery, focusing its review/copy control. A rejected destination stays in the Move sheet with an inline error, refreshed owned choices and Cancel focused. A failed ordinary read stays on its original route with Retry focused.

## Uncertain actions

While the request is pending, block duplicate submissions. After a dropped reply, focus **Check again** in the overlay or row status. Capture the originating owner/session, action, target, revision or folder snapshot. Mount that unresolved intent in the owner workspace, outside the row, list key or folder header. A refresh can remove the initiating control. Keep the status mounted on the surviving surface through a page clamp or folder canonicalization. Until resolved, block writes for that target; dirty words remain copyable. Account change clears the status and invalidates all pending callbacks before B renders.

Close and the read buttons themselves never write or navigate. Apply history changes only for verified outcomes or an authoritative clamp/canonicalization. When a check launched from an open overlay fails, dismiss that overlay locally and focus Retry on the surviving surface. A failed read never replays the mutation. Ordinary navigation after Close uses the existing dirty guard; keep the intent owner-bound and ignore stale navigation callbacks. A manual check started on another surface cannot redirect a newly selected note.
