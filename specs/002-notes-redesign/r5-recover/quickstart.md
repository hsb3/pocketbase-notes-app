# R5 implementation gates

These gates run during implementation. Use distinct disposable accounts A and B and an anonymous client. Use only the project's contained runner for servers, browsers, cron and SQLite fixtures. Record the tested commit, pre-fix commit plus test-only diff, command, numeric exit, failing assertion, project ID and three empty cleanup inventories. A skipped test, disconnected service or missing route name alone does not verify the positive behavior. Record old behavior on the previous wave with the new test harness present. A controlled failure must reach the missing behavior, then become green on the candidate. Gate staged JSVM checks only at the R5 stage so installing current hooks into the historical R4 stage continues to work.

## Staged upgrade

Extend only the existing `scripts/test-r2-upgrade.sh` fixture. Preserve its historical up/down/replay, corrupt-key rollback, source-redaction and default-folder proofs. Run R5 inside that same temporary directory after those controls. Install the genuine R5 migration and new note action/purge hook registrations only at their stage. In particular, omit the daily purge registration from the historical R4 hook copy so an overnight run cannot purge R4's expired test rows. Verify the head filename from _migrations before any down. Take snapshots with the server stopped and empty hooks for offline migration inspection. Avoid a startup reapplying migrations during down inspection.

1. From the final R4 state, snapshot complete notes, folders and attachments ordered by ID, fields, all rules, logical/physical indexes and history. Include active and already-deleted rows, the R4 title-boundary and embedded-NUL key byte checks. Confirm the old unfiltered owner list includes a known deleted row. For the pre-feature red run, issue the new expected exclusion against this real R4 endpoint before attempting to copy a migration file. Retain the unexpected ID and failing assertion.
2. Up. Require a single new history entry, new list rule, exact partial-index predicate and ordered keys using both collection metadata and SQLite index_list/index_xinfo/sqlite_master. Verify all preexisting rows, the R4 index and other metadata are equal to baseline. Require a positive active row and absent deleted row on an unfiltered owner list. Use the existing staged --dev segment isolation and a genuine canonical R4 marked page with the same synthetic owner/term. Verify both compiled empty-date disjunctions, owner test, sort, projection, literal LIKE escape and LIMIT. On the very same PocketBase engine run EXPLAIN QUERY PLAN on the complete checked SELECT, excluding COUNT. Require R4 index owner seek without temporary page sort. Run the exact bound purge candidate query and EXPLAIN. Require ordered range search on idx_notes_purge. Retain SQLite version, synthetic SELECTs and plans.
3. **Write after up.** Owner-create a new note. Edit a pre-up note using its current revision and change its body-only search term. Verify the new/edited owner GETs, keys and revisions. In the contained admin fixture soft-delete one of those rows with a known millisecond instant. Snapshot *all* rows and metadata after writes. W3 adds real owner move, individual delete, restore and confirmed custom folder delete before taking this snapshot. Include a newly created note whose folder was actually removed and verify its empty relation.
4. Stop the server, verify R5 is the newest migration, supply confirmation to migrate down 1, require its history entry gone, exact prior rules, fields and both kinds of index metadata. Compare **every current row**, including new/edited/deleted rows, to post-write snapshots byte-for-byte. Compare folder absence too. Reapply the original migration, require identical post-write rows and R5 metadata/history and repeat positive owner search plus deleted exclusion on the live server. Abort controls: in the same disposable stage arrange unexpected same-name index metadata, verify the up refuses it and leaves rule, history and rows unchanged. Restore that fixture before positive replay. A zero exit with an unconsumed down confirmation or no new row is a failure.

## Browser gates

Each browser wave must use Chromium and WebKit at 390×844, 810×1080 and 1440×1000, with zero retries. Use the existing session fixtures and note helpers. Independently GET the saved record and poll for exact state after UI actions. Use interception only to delay/release or drop the reply to a genuine mutation, or to exercise an error path. Include a real write/read positive control. For each new regression keep a product red before implementing its behavior. Already-green protection cases are controls.

**W4 · file an open note.** Open Notes → note, then from an R4 page-two body search. Cancel menu/sheet via keyboard, Escape, Close and Cancel. Assert current URL/history index, focus, revision, folder and content. Move a clean note, then type and save at the new revision. In the same search the row still matches, shows its new folder and original highlight. Back restores query/page/scroll and row. In an ordinary source folder the row vanishes. Check destination membership, clamped last page, focus fallback and bare detail Back. Exercise individual delete Cancel and Confirm from ordinary/search and deep link, verify the POP vs REPLACE contract and immediate removal. Test Save and continue / Discard / Keep editing with failed or held R3 autosave, correct post-flush revision, single mutation, preserved words, URL and focus. Drop replies to move/delete after real commit. Check again reconciles without a second revision. Reject stale action in a second context. Delete the open source from another context while local words are unsaved. Release the editor's save and require copyable exact latest words, no Saved, no recreation, authoritative tombstone unchanged. Exercise manual selection/copy when clipboard access is denied and late replies across account changes.

**W5 · folder recovery.** Drive Folders → custom folder → Delete folder with keyboard. Cancel changes no membership, revisions, dates or history. Check name/count/explanation, stale preview with equal count demands new confirmation, then actual folder disappearance and All Notes focus. Default has no destructive control. Open Recently Deleted on phone and wide. Verify every shown deadline against stored UTC data, localized label including zone, exact rows, accessible Restore, previous/next pages, zero/failed/read-retry states, 409 refresh and 410 expiry. Restore one individually deleted note to original folder and a note from the deleted folder to Notes, verify exact content, file references, original search match and new revision. Test ambiguous restore and folder delete with committed-but-dropped replies. Cover direct trash URL/reload, invalid URL cleanup, POP/Forward, guarded departure from a dirty wide editor, page clamp and row focus after restore. Switch accounts while a previous trash/preview response is held. B sees none of A's content.

**Captures.** Use the app theme switch and keyboard-only journeys. In every engine/width/theme assert visible focus, no horizontal document overflow and intended visible panes. Save PNGs under /tmp/r5-views in the browser container named ENGINE-WIDTH-THEME-STATE.png. W4 requires move-sheet and delete-note (24 files). W5 adds folder-confirm, trash-filled and trash-empty (60 total including W4). Copy reports and available PNGs out on pass/failure before teardown. A green focused run requires the full expected matrix with nonempty images and all discovered R5 cases passing once, no skips. Inspect screenshots for clipped names, time zone/deadline, contrast, controls and focus. Keep synthetic data only.
