# R5 implementation gates

These gates run during implementation. Use distinct disposable accounts A and B and an anonymous client. Use only the project's contained runner for servers, browsers, cron and SQLite fixtures. Record the tested commit, pre-fix commit plus test-only diff, command, numeric exit, failing assertion, project ID and three empty cleanup inventories. Keep each test's evidence separately. Include the reachable request, response, authoritative before/after rows, failed assertion and its later green result. Identify the test-only or partially staged diff on top of the exact predecessor. Use these classes throughout the ledger.

| Evidence class | Runnable contrast and what it establishes |
|---|---|
| Endpoint availability | W1 → W2: a valid owner POST to the new move path reaches the router and returns 404. W2 → W3: delete-preview is missing and expired-notes is absent from the admin job list. These prove registration only. |
| Reachable predecessor behavior | R4 unfiltered list returns the known deleted ID alongside the active positive. On W1 a raw malformed nonempty date can be read as empty by the owner detail handler; exercise an ordinary current-revision content PATCH on a separate malformed fixture and inspect the stored bytes. On W2, issue an owner DELETE of a **nonempty** custom folder with an independently computed matching digest; the existing hook returns 400 and every row survives. In W4/W5 record the actual predecessor screen or wrong history/focus that the new assertion observes. |
| Behavior behind a new handler | First add the tests. Stage the genuine production registration, owner guard, payload decoding and transaction path sufficiently to reach each assertion. For example, with the success path in place and the revision check still pending, send a stale Move and observe the wrong status/write; stage delete and restore at their own expected state, and check each. With restore working on retained rows, test equality/past cutoff before adding the clock refusal. With folder preview/confirm wired, test stale digest, partial rollback and write set; with a real registered job and a working first page, test progress, completion, audit keys and storage. Keep each partial red in disposable state before filling the missing behavior. Recreate fixtures between trials. Never weaken an existing safeguard or ship an intentionally partial handler. |
| Existing controls | Owner/A vs B/guest reads, protected file bytes, bare empty 204/nonempty 400, R3 saved words, R4 filtered visibility and existing search order may already pass. Preserve these greens as controls. A 404 before the handler, setup failure, or missing selector proves none of the mutation, time, race or focus outcomes. |
